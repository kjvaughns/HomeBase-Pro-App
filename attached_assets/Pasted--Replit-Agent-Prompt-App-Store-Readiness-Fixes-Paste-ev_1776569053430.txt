## Task 3 — Harden JWT_SECRET fallback (server only, no iOS rebuild needed)

**File:** `server/auth.ts`

**Current code (lines ~8–25):**

```ts
const IS_PROD = process.env.NODE_ENV === "production";

if (!process.env.JWT_SECRET) {
  if (IS_PROD) {
    console.error(
      "[auth] CRITICAL: JWT_SECRET is not set in the production environment. " +
      "Sessions will not persist across server restarts. " +
      "Set JWT_SECRET in Replit Secrets to fix this permanently."
    );
  } else {
    console.warn("[auth] JWT_SECRET not set — using dev fallback. DO NOT use in production.");
  }
}

const _generatedSecret = randomBytes(64).toString("hex");

export const JWT_SECRET =
  process.env.JWT_SECRET || (IS_PROD ? _generatedSecret : "homebase-jwt-secret-dev-only");
```

**Replace with:**

```ts
const IS_PROD = process.env.NODE_ENV === "production";

if (IS_PROD && !process.env.JWT_SECRET) {
  console.error(
    "[auth] CRITICAL: JWT_SECRET is not set in production. Refusing to start. " +
    "Set JWT_SECRET in Replit Secrets."
  );
  process.exit(1);
}

if (!IS_PROD && !process.env.JWT_SECRET) {
  console.warn("[auth] JWT_SECRET not set — using dev fallback. DO NOT use in production.");
}

export const JWT_SECRET =
  process.env.JWT_SECRET || "homebase-jwt-secret-dev-only";
```

**Why:** The current code generates a random in-memory secret in production if the env var is missing, which silently invalidates every user's session on every restart and breaks horizontal scaling. Fail-loud is the right behavior — you'd rather a crashed deploy than a fleet of broken sessions.

## Task 4 — Move sessionToken to expo-secure-store (requires native rebuild)

**Files:** `client/state/authStore.ts`, `package.json`

**Steps:**

1. Install the dep:
   ```bash
   npx expo install expo-secure-store
   ```
2. Create a new file `client/lib/secureSession.ts`:
   ```ts
   import * as SecureStore from "expo-secure-store";
   import { Platform } from "react-native";

   const SESSION_TOKEN_KEY = "homebase_session_token";

   /**
    * Session token storage. Uses Keychain on iOS / Keystore on Android via
    * expo-secure-store. Falls back to a no-op on web where SecureStore isn't
    * available — web users re-auth via cookie anyway.
    */
   export async function setSessionToken(token: string | null): Promise<void> {
     if (Platform.OS === "web") return;
     if (token === null) {
       await SecureStore.deleteItemAsync(SESSION_TOKEN_KEY);
     } else {
       await SecureStore.setItemAsync(SESSION_TOKEN_KEY, token, {
         keychainAccessible: SecureStore.AFTER_FIRST_UNLOCK,
       });
     }
   }

   export async function getSessionToken(): Promise<string | null> {
     if (Platform.OS === "web") return null;
     try {
       return await SecureStore.getItemAsync(SESSION_TOKEN_KEY);
     } catch {
       return null;
     }
   }
   ```
3. In `client/state/authStore.ts`:
   - On `login`: after the existing `sessionToken` state update, call `await setSessionToken(token)`.
   - On `logout`: call `await setSessionToken(null)` before the state reset.
   - In the `hydrate()` function: after reading from `AsyncStorage.getItem(STORAGE_KEY)`, also call `await getSessionToken()` and prefer that value for `sessionToken` (to migrate existing installs). If the stored auth-storage JSON already has a `sessionToken`, write it to secure storage on migration and strip it from the JSON blob on the next save.
   - In the persisted JSON (line ~274 where `JSON.stringify(data)` is called): exclude `sessionToken` from the serialized payload — sessionToken lives only in SecureStore now.

**Why:** AsyncStorage is NSUserDefaults; Keychain is the right home for a 7-day JWT.

```js
      NSPrivacyAccessedAPITypes: existing.NSPrivacyAccessedAPITypes || [],
    };

    fs.writeFileSync(manifestPath, plist.build(merged));
    return cfg;
  });
```
