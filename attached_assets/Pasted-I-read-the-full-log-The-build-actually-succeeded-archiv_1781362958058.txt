I read the full log. The build actually **succeeded** — archive compiled clean. It failed on the very last step. Here's exactly what happened:

---

## The Real Error

```
Error: Cannot find module '@sentry/cli/package.json'
Script 'Upload Debug Symbols to Sentry' failed
```

The Sentry debug symbol upload script runs after the archive is built, can't find `@sentry/cli` in the EAS build environment, and crashes — which kills the entire build with exit code 65.

That's it. One missing package at the end of an otherwise successful build.

---

## Why It's Happening

EAS Build installs your `dependencies` and `devDependencies` from `package.json`, but `@sentry/cli` is likely either missing from your `package.json` entirely, or it's there but not resolving correctly in the EAS cloud environment because the Sentry Xcode build phase script is looking for it in a path that doesn't exist on the build machine.

## Two Other Warnings to Note (Non-Fatal But Worth Knowing)

From the log — these didn't cause the failure but will eventually need fixing:

**Warning 1:** `Pods/Sentry-Sentry: iOS@11.0 deployment version mismatch` — your iOS deployment target in the Podfile is set lower than what Sentry expects. Set it to iOS 14+ in your `app.json` under `ios.deploymentTarget`.

**Warning 2:** `ld: search path not found` for Metal toolchain — harmless on EAS, ignore it.

The Sentry symbol upload is the only actual blocker. Fix that and this build ships.
